# ADR-11: Una única frontera en C entre el núcleo y las apps

- **Estado:** Aceptada
- **Fecha:** 2026-11-07
- **Referencia:** apartado 10 del documento de arquitectura y requisitos

## Contexto

Kotlin llega al núcleo por JNI y Swift lo importa como módulo C. Una excepción C++ que cruce la frontera termina el proceso, y enlazar clase a clase multiplica el código de unión.

## Decisión

El núcleo expone solo una API en C (`core/include/mc/mc_api.h`): sesiones opacas, comandos y respuestas JSON en bytes, ninguna excepción ni hilo propio, y búferes que se liberan con `mc_buffer_free`.

## Alternativas descartadas

- Interoperabilidad directa Swift-C++: no captura excepciones.
- Enlazar clase a clase por JNI: más código que mantener.

## Consecuencias

- Funciones: `mc_version`, `mc_pack_verify`, `mc_session_create`, `mc_session_dispatch`, `mc_buffer_free` y `mc_session_destroy`.
- Comandos actuales: `pack_info` y `validate_deck`. Errores: `invalid_json`, `missing_cmd`, `unknown_command`, `bad_deck`, `bad_pack`, `too_large` e `internal`.
- La biblioteca compartida exporta solo esas seis funciones (lista de símbolos `core/mc_core.map`).
- Una sesión se usa desde un solo hilo o actor.
