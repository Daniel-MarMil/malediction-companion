# ADR-11: A single C boundary between the core and the apps

- **Status:** Accepted
- **Date:** 2026-11-07
- **Reference:** section 10 of the architecture and requirements document

## Context

Kotlin reaches the core through JNI, and Swift imports it as a C module. A C++ exception that crosses the boundary terminates the process, and binding class by class multiplies the glue code.

## Decision

The core exposes only a C API (`core/include/mc/mc_api.h`): opaque sessions, JSON commands and replies as bytes, no exceptions and no threads of its own, and buffers that are freed with `mc_buffer_free`.

## Rejected alternatives

- Direct Swift and C++ interoperability: it does not catch exceptions.
- Binding class by class through JNI: more code to maintain.

## Consequences

- Functions: `mc_version`, `mc_pack_verify`, `mc_pack_verify_trusted` (since 2026-11-09, ADR-06), `mc_session_create`, `mc_session_dispatch`, `mc_buffer_free` and `mc_session_destroy`.
- Current commands: `pack_info` and `validate_deck`. Errors: `invalid_json`, `missing_cmd`, `unknown_command`, `bad_deck`, `bad_pack`, `too_large` and `internal`.
- The shared library exports only those seven functions (symbol list `core/mc_core.map`).
- A session is used from a single thread or actor.
