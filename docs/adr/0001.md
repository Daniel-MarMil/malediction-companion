# ADR-01: Shared C++20 rules and protocol core

- **Status:** Accepted
- **Date:** 2026-11-07
- **Reference:** section 10 of the architecture and requirements document

## Context

The Android app, the iOS app and the server must apply exactly the same Malediction rules: deck building, echo and mastery counters, and the match protocol. Local matches must also work without a network.

## Decision

The rules, the domain, the protocol and the event reducer live in a C++20 library of our own, with no graphical interface and no input/output. Both apps and the server use it.

## Rejected alternatives

- Duplicating the rules on each platform: three implementations that drift apart.
- Rules only on the server: they make playing without a network impossible.

## Consequences

- A single implementation, tested once (RNF-17: 90 % coverage and property-based tests).
- Memory safety becomes an explicit requirement (RNF-19): warnings as errors, sanitizers and fuzzing.
- A stable bridge to Kotlin and Swift is needed: ADR-11.
- Phase 0: the library is in `core/`, with the rules pack, deck validation and signature verification.
