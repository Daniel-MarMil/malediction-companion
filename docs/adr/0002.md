# ADR-02: Native user interfaces on top of the C++ core

- **Status:** Accepted
- **Date:** 2026-11-07
- **Revision:** 2026-11-08: the iOS app moves to phase 5 and the first final version ships only on Android
- **Reference:** section 10 of the architecture and requirements document

## Context

The apps need good accessibility (TalkBack and VoiceOver), system controls and a modest download size. Qt 6 Quick raised doubts about LGPLv3 on the App Store and had accessibility bugs on iOS.

## Decision

Android uses Kotlin with Jetpack Compose (Material 3) and iOS uses Swift with SwiftUI. Both call the C++ core through its C API.

## Rejected alternatives

- Qt 6 Quick: doubts about LGPLv3 on the App Store and accessibility bugs on iOS.
- Flutter with dart:ffi: moves the interface to Dart, without the system controls.
- Slint: because of its license.

## Consequences

- Two interfaces to maintain; RNF-21 requires both to pass the same acceptance scenarios.
- The iOS app needs a Mac with Xcode. There is none now and no date to get one, so Android goes first: the first final version ships only on Android (phase 4) and the iOS app waits for phase 5.
- Better accessibility and smaller apps than with a cross-platform framework.
