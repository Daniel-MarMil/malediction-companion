# ADR-03: Server as a modular C++20 monolith with Drogon and PostgreSQL

- **Status:** Accepted
- **Date:** 2026-11-07
- **Reference:** section 10 of the architecture and requirements document

## Context

The server coordinates online matches and stores accounts and history. It shares the core with the apps, and the team is small.

## Decision

A single C++20 service with Drogon (MIT), split into internal modules, with PostgreSQL as the database.

## Rejected alternatives

- Boost.Beast: lower level, with more code of our own.
- Microservices: too much operational work for the size of the team.
- Firebase: it hosts data outside the EEA (ADR-07).

## Consequences

- The server reuses the core without translation layers.
- It will be decided when the online match phase starts.
